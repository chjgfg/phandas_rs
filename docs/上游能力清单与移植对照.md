# 上游 phandas 能力清单与 Rust 移植对照

记录 Python 版 phandas 的全部能力，以及本仓库 `src/` 的覆盖情况，供后续补齐移植时查阅。

- **上游**：`D:\develop\workspace\python_workspace\phandas_public`，`__version__ = "0.18.1"`，作者 Phantom Management，MIT。
- **本仓库**：`phandas_rs`，覆盖因子构造（`src/factor/`）、事件驱动回测（`src/backtest/`）与因子评价（`src/analysis/`），零外部依赖。
- **口径**：行数为 `wc -l` 实测；签名照抄上游源码（含默认值）；"一致 / 有差异"的判定来自一次逐格差分测试，方法见第 6 节。
- **记录日期**：2026-09-03。上游未打 tag，后续比对前请先确认上游源码未变。

### 2.6 二元运算（10 个，右操作数可为因子或标量）

Rust 用 `impl Into<Operand<'a>>` 统一接收 `&Factor` 与 `f64`。

| Python | Rust | 备注 |
|---|---|---|
| `add(other)` | `add(impl Into<Operand>)` | |
| `subtract(other)` | `subtract(..)` | |
| `multiply(other)` | `multiply(..)` | |
| `divide(other)` | `divide(..)` | 因子除数 `|y| <= 1e-10 → NaN`；标量除数为 0 → 整体 NaN |
| `power(exponent)` | `power(..)` | `±inf` 归 NaN |
| `signed_power(exponent)` | `signed_power(..)` | `sign(x)·|x|^e` |
| `maximum(other)` | `maximum(..)` | 任一为 NaN → NaN（`np.maximum` 语义） |
| `minimum(other)` | `minimum(..)` | 同上 |
| `reverse()` | `reverse()` | = `multiply(-1)` |
| `where(cond, other=np.nan)` | `where_cond(&cond, impl Into<Operand>)` | 自由函数 `where_(&cond, &x, y)`（`where` 是 Rust 关键字）；Rust 无默认值，`other` 必须显式传 |

二元运算都按 `(timestamp, symbol)` 取交集，等价于 `pd.merge(how='inner')`。

标量在左的三个（对应 Python 的反射运算符）另有方法形式，实现在 `arith.rs`：

| 语义 | Rust 方法 | Rust 运算符 | 因子名 |
|---|---|---|---|
| `lhs - self` | `scalar_sub(f64)` | `2.0 - &f` / `2.0 - f` | `(2-close)` |
| `lhs / self` | `scalar_div(f64)` | `2.0 / &f` / `2.0 / f` | `(2/close)` |
| `base ^ self` | `scalar_power(f64)` | 无（Rust 没有 `**`） | `(2**close)` |

`2.0 + &f` / `2.0 * &f` 直接转发到 `add` / `multiply`，因子名是 `(close+2)` / `(close*2)`——与 Python 的 `__radd__` / `__rmul__` 转发给正向方法后的命名一致。

⚠️ `scalar_div` 的除零判据是**精确等零**，而 `divide` 的因子除数判据是 `|y| > 1e-10`。这是如实复刻上游 `__rtruediv__` 与 `__truediv__` 的不一致：`2.0 / &f` 在 `f` 极小但非零处会得到极大值（上游此处也没做 inf 清理），而 `&g / &f` 在同一位置得 NaN。

### 2.7 比较与运算符重载

| Python | Rust | 状态 |
|---|---|---|
| `__lt__` `__le__` `__gt__` `__ge__` | `lt` `le` `gt` `ge` | ✅ 返回 `1.0`/`0.0` 因子 |
| `__eq__` `__ne__` | `eq_val` `ne_val` | ✅ 改名以免与 `PartialEq` 冲突 |
| `__add__` `__sub__` `__mul__` `__truediv__` | `impl Add/Sub/Mul/Div`，左值可借用或拥有，右值可为 `&Factor` 或 `f64` | ✅ |
| `__neg__` | `impl Neg` | ✅ |
| `__abs__` | `abs()` 方法 | ✅ |
| `__pow__` | `power()` 方法 | ✅ Rust 无 `**` 运算符 |
| `__radd__` `__rmul__` | `impl Add/Mul<&Factor \| Factor> for f64` | ✅ 转发到 `add` / `multiply` |
| `__rsub__` `__rtruediv__` | `impl Sub/Div<&Factor \| Factor> for f64` | ✅ 见 2.6 的 `scalar_sub` / `scalar_div` |
| `__rpow__` | `scalar_power()` 方法 | ✅ 无运算符形式 |

给外部类型 `f64` 实现外部 trait 之所以合法：`&` 是 `#[fundamental]`，`&Factor` 与 `Factor` 都算本 crate 的本地类型，孤儿规则放行。反过来，**下游 crate 无法自行补这几个 impl**，只能由本 crate 提供——和 Python 侧改不了 `int` / `float` 的 `__sub__`、只能定义 `__rsub__` 是同一个道理。

### 3.3 本仓库比上游正确的三个算子（⚠️ 这条偏差尚未写进 `mod.rs` 文档）

`ts_corr` / `ts_covariance` / `ts_autocorr`（后者建立在前者上）。差异范围很大：`ts_corr(window=3)` 在 48 格里 39 格不同。

根因在上游 `core.py:903`（`ts_corr`）与 `core.py:936`（`ts_covariance`）：

```python
result['factor'] = merged.groupby('symbol', group_keys=False).apply(
    safe_corr, include_groups=False
).values          # ← 位置赋值
```

`safe_corr` 返回的是 `group[['factor_x','factor_y']].rolling(w).corr().iloc[0::2, -1]`，索引是 MultiIndex，走不到 pandas 的 transform 对齐路径；于是各组结果按**分组顺序**拼接后被 `.values` 硬塞回按 `(timestamp, symbol)` 排序的行上。**只要标的数 > 1，结果就串到别的格子里**，且长度恰好相等所以不报错。

最小复现（x：AAA = 1,2,3,4 递增 / BBB = 4,3,2,1 递减；y：两标的都是 1,2,3,4；`window=3`）：

| | 正确答案 | 上游输出 |
|---|---|---|
| AAA | NaN, NaN, **+1**, **+1** | NaN, **1.0**, NaN, **-1.0** |
| BBB | NaN, NaN, **−1**, **−1** | NaN, **1.0**, NaN, **-1.0** |

拼接数组 `[NaN,NaN,1,1, NaN,NaN,-1,-1]` 按位置塞进 `(ts,sym)` 序的 8 行。症状：首个有效值提前一期出现，且同一期不同标的取到同一个数。本仓库给的是正确值。

同样的 `.values` 写法在 `ts_regression`（`core.py:1035`）也有，但那里返回的是普通 `group.index` 的 `Series`，走到了 transform 路径，所以没问题——差分测试里 rettype 0–7 全部逐格一致，正好印证。

**处理方式**：保留正确实现，并已在 `src/factor/mod.rs` 的"与 Python 版的已知偏差"里记下这条。若日后需要与上游逐值对齐（例如复现历史回测），再单独提供一个复刻错位的开关，不要改动现有实现。

### 3.4 一处浮点刀锋（不算缺陷）

`ts_regression(rettype=9)` 在完美拟合的窗口上：上游 SSE 是 `7e-15` 量级的浮点残渣，`MSE > 0` 成立，给出 `~1e-15` 的标准误；本仓库 SSE 恰为 0，`mse > 0.0` 不成立 → NaN。48 格里 2 格。两边说的是同一件事。

### 3.5 已在 `mod.rs` 中声明的既有偏差

- `norm.ppf` 用 Acklam 有理逼近，相对误差约 `1e-9`（scipy 为机器精度）。
- 时间戳按字符串字典序排序，要求 ISO-8601 输入。
- `ts_rank` 并列时用稳定排序。
- 上游在"全为 NaN"或"合并结果为空"时抛异常，本仓库一律返回全 NaN / 空因子。
- `ts_step` 沿完整时间轴计数（见 2.4）。
- `ts_decay_linear` 权重方向与 `ts_decay_exp_window` 相反（如实复刻）。
- `ts_skewness` 由算子复合而成，需 `2×window-1` 期（如实复刻）。
- `spread` 用 `np.argsort` 的"NaN 排末尾"语义挑多头，当期有 NaN 时多头名额会被 NaN 占用（如实复刻）。
- `ts_regression(rettype=8)` 单自变量下上游抛 `IndexError`，本仓库返回 NaN。
- `scalar_div`（`2.0 / &f`）除零判据是精确等零，与 `divide` 的 `|y| > 1e-10` 不一致——这是上游 `__rtruediv__` 与 `__truediv__` 本身的不一致（见 2.6）。

#### 与上游的差异

1. **IC 口径只认 `spearman` / `pearson`**。上游 `_compute_ic_vectorized` 只判断
   `method == 'spearman'`，传别的字符串（含 `'kendall'`）**静默按 Pearson 算**；
   本仓库由 [`IcMethod`] 枚举约束，未知取值直接 `Err`。
2. **同一实例的 `ic()` 不受方法缓存污染**。上游 `_ic_cache` 不区分 `method`，
   对同一 `FactorAnalyzer` 先 `ic('spearman')` 再 `ic('pearson')`，第二次返回的是
   spearman 缓存（对比差分测试踩到的坑）；本仓库每次调用按需重算，无此问题。
3. `summary` / `correlation` 不打印也不发 `warnings.warn`：样本不足时上游发警告并返回
   空 `DataFrame`，本仓库返回空的 [`CorrMatrix`]。
4. 如实复刻的上游细节：`ic_std` 用 numpy 的 `ddof = 0`（不是 pandas 的 1）；
   `_compute_ic_vectorized` 分子只累加两侧同时非 NaN 的格子、分母却各自累加单侧全部
   有效格（两侧 NaN 分布不同时 `|IC|` 被压低，不一定落在 `[-1, 1]`）；`ir` / `t_stat`
   在 `ic_std` 非正时为 `0.0`；`stats.autocorr` 只在剔除 NaN 后样本数 > 10 时计入。
5. 相关性样本 = 各因子 `signal()` 在 (timestamp, symbol) 交集上"全部因子都非 NaN"的格子，
   与上游 `DataFrame(aligned).dropna()` 后 `.corr` 的**完整样本**语义一致（上游先 dropna
   再逐对算，故逐对样本即全局样本）。上游用 dict 收集堆叠序列、因子同名会互相覆盖；
   本仓库按传入顺序存名，重名不合并。
6. `stats.turnover` 是**两级平均**：`DataFrame.mean()` 默认 `axis = 0`，故上游
   `rank_diff.mean().mean() * 2` 先给每个标的算一个均值（跳 NaN）、再对标的取均值，
   与"把所有格子池化求一个均值"在各标的有效差分个数不齐时并不相等（面板里 `close`
   只缺 `(2024-01-04, AAA)` 一格，两者就是 0.14267676767676768 与 0.14682539682539683
   之别）。只有 0 期或 0 标的（上游 `rank_diff.empty` 为真）时给 `0.0`，其余算不出来
   的情况是 NaN——只有 1 期、或差分整块全 NaN 都属此类；`summary()` 里 NaN 按 Python
   `f"{nan:.4f}"` 渲染成小写 `nan`。
7. `correlation()` 的对角线：pandas 的 `method='kendall'` 不走 `nancorr` 而走 `nanops`
   的逐对循环，把 `i == j` **硬编码成 `1.0`**（在方差检查之前），故常量列在该口径下
   对角线是 1.0；Pearson / Spearman 走 `nancorr`，同样情形给 NaN。本仓库在
   `correlation()` 这一层照做，`analysis::corr` 本身仍按 scipy 给 NaN。
8. `analysis::corr` 三个口径遇 NaN 一律返回 NaN：Pearson / Spearman 由 NaN 自然传播，
   Kendall 显式挡在函数入口（早先靠排序里的 `expect` 兜底，会 panic）。

#### 验证结果

差分测试 `tests/test_upstream_analysis.rs`（`#[ignore]`）+ `.omc/difftest/run_py_analysis.py` /
`compare_analysis.py`，读同一份 `tests/data/panel.csv`，价格 = `close`、因子 =

`_calculate_performance_metrics(returns, risk_free_rate=0.03, annualization_factor=365.0)` 的口径（照抄源码）：

```
equity        = (1 + returns).cumprod()
total_return  = equity[-1] - 1
days          = (index[-1] - index[0]).days        # 日历天数，不是交易日
annual_return = (1 + total_return) ** (365 / days) - 1
annual_vol    = returns.std() * sqrt(365)
sharpe        = (annual_return - 0.03) / annual_vol
drawdown      = equity / equity.expanding().max() - 1
max_drawdown  = drawdown.min()
calmar        = annual_return / abs(max_drawdown)
linearity     = linregress(arange(n), equity).rvalue ** 2
downside_vol  = returns[returns < 0].std() * sqrt(365)
sortino       = (annual_return - 0.03) / downside_vol
var_95        = returns.quantile(0.05)
cvar          = returns[returns <= var_95].mean()
```

#### 与上游的差异

1. **`full_rebalance = true` 只记一条净值**。上游每个交易日调 `update_market_value` 两次（清仓前后各一次），`history` 同一天两条：收益率序列长度翻倍，年化波动 / 夏普 / 索提诺失真；`turnover` 用 `pd.DataFrame` 对齐重复索引还会抛异常，连带 `summary()` 在该模式下不可用。实测上游该场景 12 个交易日给出 **23** 条净值，本仓库给 12 条。
2. **`Neutralization::parse` 对未知字符串返回 `Err`**，上游只特判 `"none"`，其余（含拼错的）静默按市场中性处理。
3. `summary` / `drawdown_report` 返回 `String` 而非打印；没有 `plot_equity` 与 `to_dict`。

如实保留的上游行为：逐期缓存里**当期任一标的为 NaN 就整期丢弃**（价格与策略两侧都是）；**前一期策略数据被丢弃时目标市值为空，当期清空全部持仓**；目标市值用清仓**前**的净值算，而下单比对的是清仓**后**的持仓；年化按日历天数 365、无风险利率默认 0.03。

#### 验证结果

差分测试三个场景（详见第 6 节），容差 1e-9：

| 场景 | 路径 | 净值 | 收益率 | 11 项指标 | 回撤区间 | 成交笔数 |
|---|---|---|---|---|---|---|
| `A_signal` | 因子已是信号，直通 | ✅ 12/12 | ✅ 11/11 | ✅ | ✅ | ✅ 44 |
| `C_rank` | 去均值归一 | ✅ 12/12 | ✅ 11/11 | ✅ | ✅ | ✅ 44 |
| `B_signal_fr` | `full_rebalance=true` | ⚠️ 12 vs 23 | ⚠️ | ⚠️ | ⚠️ 2 vs 3 段 | ✅ 68 |

`B_signal_fr` 的成交笔数与上游一致（68 = 68），说明交易逻辑相同，差异只出在净值记录点——正是上面第 1 条的预期后果。

| `phmin/` | 上游 `core.py` / `panel.py` / `operators.py` / `constants.py` / `backtest.py` / `analysis.py` / `console.py` 的原样副本 + 空 `__init__.py` + 一个 `plot.py` 空壳（只提供 `_DATE_FORMAT` 与空 `BacktestPlotter`，避开 matplotlib），用来绕开 `phandas/__init__.py` 对 ccxt 的依赖 |
| `run_py.py` | 在上游实现上跑同样 122 个算子调用点，读 `tests/data/panel.csv`，输出 `out_py.csv`（`op,ts,symbol,value`，17 位有效数字，NaN 写 `nan`） |
| `compare.py` | 按 `(算子, timestamp, symbol)` 逐格比对 `out_py.csv` 与 `target/upstream_diff_rs.csv`，容差 `atol=rtol=1e-9`，按算子汇总 |
| `run_py_backtest.py` | 在上游回测实现上跑三个场景，输出 `bt_py.csv`（`场景,类别,键,值`） |
| `compare_backtest.py` | 按 `(场景, 类别, 键)` 逐格比对 `bt_py.csv` 与 `target/upstream_backtest_rs.csv` |
| `run_py_analysis.py` | 在上游因子评价实现上跑同一场景（因子 = `[signal(rank(close)), rank(close), close, volume]`），输出 `analysis_py.csv`（`组,键,值`）。注意每个口径都新建 `FactorAnalyzer`——同一实例第二次 `ic()` 会返回第一次的缓存（上游 `_ic_cache` 不分方法） |
| `compare_analysis.py` | 按 `(组, 键)` 比对 `analysis_py.csv` 与 `target/upstream_analysis_rs.csv`，NaN 两侧都写 `nan` |
| `ref_stats.py` | 从 scipy / pandas 取一组参考值（分位数、偏度、峰度、`norm.cdf`、完整指标），用来钉住 `tests/test_backtest.rs` 里的断言 |
| `patch_harness.py` / `make_integration_test.py` | 一次性迁移脚本（已执行完）：前者把反射运算符的占位改成真实调用，后者把临时 harness 转成正式集成测试 |

**跑法**

```bash
# 算子
cargo test --test test_upstream_diff -- --ignored --nocapture      # → target/upstream_diff_rs.csv
cd .omc/difftest && python run_py.py && python compare.py

# 回测
cargo test --test test_upstream_backtest -- --ignored --nocapture  # → target/upstream_backtest_rs.csv
cd .omc/difftest && python run_py_backtest.py && python compare_backtest.py

# 因子评价
cargo test --test test_upstream_analysis -- --ignored --nocapture  # → target/upstream_analysis_rs.csv
cd .omc/difftest && python run_py_analysis.py && python compare_analysis.py
```

两侧必须读同一份 `tests/data/panel.csv`；改动那份数据后两边都要重跑。

**另一个已删的探针**：`window = 0` 行为核查——把 22 个 `ts_*` 各调一次 `window=0`，用 `catch_unwind` 记录哪些 panic。结论见 3.2 的 P0。要重跑就照样在 `tests/` 下新建一个 `#[ignore]` 集成测试。
